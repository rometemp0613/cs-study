# Part 1-2: 관계형 데이터 모델

## 관계형 데이터 모델이란?

- 1970년 **E.F. Codd** 박사가 제안
- 핵심 아이디어: **모든 데이터를 2차원 테이블(릴레이션)로 표현**

---

## 릴레이션의 구성 요소

```
┌──────────┬──────────┬──────────┬─────────┐
│ 학번(PK) │  이름    │  학과    │  학년   │  <- 속성(Attribute) = 컬럼
├──────────┼──────────┼──────────┼─────────┤
│ 2024001  │ 김철수   │ 컴공    │   3     │  <- 튜플(Tuple) = 행
│ 2024002  │ 이영희   │ 수학    │   2     │
│ 2024003  │ 박민수   │ 컴공    │   1     │
└──────────┴──────────┴──────────┴─────────┘
         도메인(Domain) = 각 속성이 가질 수 있는 값의 범위
         예) 학년 도메인 = {1, 2, 3, 4}
```

---

## 용어 대응표

| 수학(관계형 모델) | 실무(DB) | 파일 시스템 |
|---|---|---|
| **릴레이션** (Relation) | 테이블 (Table) | 파일 (File) |
| **튜플** (Tuple) | 행 (Row) | 레코드 (Record) |
| **속성** (Attribute) | 컬럼 (Column) | 필드 (Field) |
| **도메인** (Domain) | 데이터 타입 + 제약 | - |
| **차수** (Degree) | 컬럼 수 | - |
| **카디널리티** (Cardinality) | 행 수 | - |

---

## 릴레이션 스키마 vs 릴레이션 인스턴스

| 구분 | 설명 | 비유 |
|---|---|---|
| **스키마** | 릴레이션의 구조 정의 (이름 + 속성 목록) | 클래스 (Class) |
| **인스턴스** | 특정 시점의 실제 데이터 (튜플들의 집합) | 객체 (Object) |

```
스키마:    학생(학번, 이름, 학과, 학년)
인스턴스:  { (2024001, 김철수, 컴공, 3), (2024002, 이영희, 수학, 2), ... }
```

---

## 릴레이션의 4가지 특성 (SQLP 단골!)

암기: **"유무무원"**

| # | 특성 | 설명 |
|---|---|---|
| 1 | **튜플의 유일성** | 중복된 튜플이 없다 (키가 보장) |
| 2 | **튜플의 무순서** | 행의 순서는 의미 없다 |
| 3 | **속성의 무순서** | 컬럼의 순서는 의미 없다 |
| 4 | **속성의 원자성** | 각 속성 값은 원자값 (= **1NF의 근거**) |

---

## 도메인(Domain) 상세

도메인 = 단순 데이터 타입이 아니라 **의미적으로 허용 가능한 값의 집합**

```
학년 도메인 = {1, 2, 3, 4}         <- INTEGER지만 5는 안 됨
성별 도메인 = {'M', 'F'}           <- CHAR(1)이지만 'X'는 안 됨
```

SQL에서는 `CHECK` 제약조건이나 `CREATE DOMAIN`(표준)으로 구현.

---

## 주의사항 & 흔한 실수

- **릴레이션 != 테이블**: 엄밀히 릴레이션은 수학 용어, 테이블은 실무 용어. 시험에서 구분 요구함
- **차수 vs 카디널리티 헷갈림**: 차수(Degree)=컬럼 수, 카디널리티(Cardinality)=행 수
- **1NF = First Normal Form (제1정규형)**: 속성의 원자성이 1NF의 근거
