## 5.1 fork() — 프로세스 복제

- `int rc = fork();`
- 호출한 프로세스의 **(거의) 완전한 복사본** 생성
- **호출 1번, 리턴 2번** (부모와 자식 각각에서)
- 리턴값:
  - **부모**: 자식의 PID (양수)
  - **자식**: 0
  - **실패**: 음수
- 자식은 main()부터 시작하지 않고, **fork() 호출 지점부터** 실행
- 자식은 자기만의 주소 공간, 레지스터, PC를 가짐 (복사본이지만 독립적)

```
부모 (PID: 100)
    │
    ├── printf("hello")     ← 한 번만 출력
    ├── fork() 호출
    │     │
    │     ├── 부모: rc = 200 (자식 PID)
    │     └── 자식 (PID: 200): rc = 0
```

### 비결정적 (Non-deterministic)

- fork() 후 부모와 자식 중 누가 먼저 실행될지는 **CPU 스케줄러가 결정**
- 실행할 때마다 순서가 달라질 수 있음
- 멀티스레드 프로그램에서 더 많은 비결정성 문제 발생 (Part 2에서 다룸)

## 5.2 wait() — 자식 기다리기

- `int rc_wait = wait(NULL);`
- 부모가 호출하면 **자식이 종료될 때까지 블록**
- 비결정적 실행 순서를 **결정적(deterministic)**으로 만듦
- 더 완전한 버전: **waitpid()** — 특정 자식의 PID를 지정해서 기다릴 수 있음

```
[어떤 경우든 wait() 덕분에]
자식: 실행 → 종료
                  ↓
부모: wait() → 리턴 → 계속 실행
→ 항상 자식이 먼저 끝남!
```

## 5.3 exec() — 프로그램 변신

- `execvp(myargs[0], myargs);`
- 현재 프로세스의 코드/데이터/힙/스택을 **새 프로그램으로 통째로 덮어씀**
- 새 프로세스를 만드는 게 **아님** — 기존 프로세스가 변환되는 것
- **성공하면 절대 리턴하지 않음** (원래 코드가 사라졌으므로)
- 6가지 변형: execl, execlp, execle, execv, execvp, execvpe
  - l = list (인자를 나열), v = vector (인자를 배열로)
  - p = PATH 검색, e = 환경변수 전달

## 5.4 fork()+exec() 분리의 핵심 — 셸의 비밀

### 왜 분리했나?

> fork()와 exec() **사이의 틈**에서 자식의 환경(fd 등)을 조작할 수 있어서,
> 리다이렉션이나 파이프 같은 강력한 기능을 쉽게 구현할 수 있다.

### 리다이렉션 예시: `wc p3.c > newfile.txt`

```
셸(부모)
  │
  ├─① fork() → 자식 생성
  │
  │   자식:
  │     ├─② close(STDOUT_FILENO)   ← fd 1 (stdout)을 닫는다
  │     │    fd 0: stdin
  │     │    fd 1: [비어있음!]
  │     │    fd 2: stderr
  │     │
  │     ├─③ open("newfile.txt")    ← 파일을 연다
  │     │    UNIX는 가장 낮은 빈 fd를 배정
  │     │    fd 0: stdin
  │     │    fd 1: newfile.txt  ← 여기!
  │     │    fd 2: stderr
  │     │
  │     ├─④ exec("wc", "p3.c")    ← wc로 변신
  │     │    wc의 출력 → fd 1 → newfile.txt로!
  │     └─⑤ 종료
  │
  └─⑥ wait() → 자식 끝나면 프롬프트 출력
```

### 파이프 예시: `grep -o foo file | wc -l`

- `pipe()` 시스템 콜로 커널 내 큐(파이프) 생성
- 한 프로세스의 stdout → 파이프 입력
- 다른 프로세스의 stdin → 파이프 출력
- 이것도 fork()와 exec() 사이의 틈에서 설정

### Lampson's Law

> "Get it right" — 추상화나 단순함이 올바름을 대체할 수 없다.

fork()+exec() 조합이 복잡해 보여도, UNIX 설계자들이 올바르게 설계한 것이라는 맥락.

## 5.5 프로세스 제어와 사용자

### 시그널 시스템

- **kill()**: 프로세스에 **시그널을 보내는** 시스템 콜 (죽이는 것만이 아님!)
- **signal()**: 특정 시그널을 catch해서 커스텀 처리 등록
- 주요 시그널:
  - **SIGINT** (Ctrl+C): 프로세스 종료
  - **SIGTSTP** (Ctrl+Z): 프로세스 일시 중지 → `fg`로 재개
- 개별 프로세스뿐 아니라 **프로세스 그룹** 전체에도 전송 가능

### 사용자(User) 개념

- **일반 사용자**: 자기 프로세스만 제어 가능
- **슈퍼유저(superuser, root)**: 모든 사용자의 프로세스를 제어 가능
- 보안을 위해 평소엔 일반 사용자로 사용 권장

## 5.6 유용한 도구

- `ps`: 실행 중인 프로세스 목록
- `top`: CPU/메모리 사용량 실시간 모니터링
- `kill` / `killall`: 프로세스에 시그널 전송
- **man pages**: `man fork` 등으로 시스템 콜 문서 확인 (RTFM!)

## 요약

| API | 역할 | 핵심 |
|-----|------|------|
| fork() | 복제 | 부모→자식PID, 자식→0, 실패→음수 |
| exec() | 변신 | 코드 덮어씀, 성공 시 리턴 안 함 |
| wait() | 대기 | 자식 종료까지 블록, 결정적으로 만듦 |
| kill() | 시그널 전송 | 종료뿐 아니라 다양한 시그널 |
| pipe() | 파이프 생성 | 프로세스 간 출력→입력 연결 |
