# 새로 배운 용어/개념

## Ch.5 프로세스 API

- **fork() 시스템 콜**: 호출한 프로세스의 (거의) 완전한 복사본을 생성. 호출 1번, 리턴 2번. 부모→자식PID(양수), 자식→0, 실패→음수
- **wait() 시스템 콜**: 부모가 호출하면 자식이 종료될 때까지 블록. 비결정적 실행 순서를 결정적으로 만듦
- **exec() 시스템 콜**: 현재 프로세스의 코드/데이터/힙/스택을 새 프로그램으로 덮어씀. 새 프로세스를 만드는 게 아니라 기존 프로세스를 변환. 성공하면 절대 리턴하지 않음
- **fork()+exec() 분리 이유**: fork()와 exec() 사이의 틈에서 fd를 조작할 수 있어서 리다이렉션/파이프를 쉽게 구현할 수 있다
- **셸의 리다이렉션 원리**: fork() 후 자식에서 close(stdout) → open(파일) → exec(). UNIX는 가장 낮은 빈 fd를 배정하므로 fd 1에 파일이 들어감
- **비결정적 (Non-deterministic)**: fork() 후 부모와 자식 중 누가 먼저 실행될지 CPU 스케줄러가 결정하므로 예측 불가
- **SIGINT / SIGTSTP**: SIGINT(Ctrl+C)는 프로세스 종료, SIGTSTP(Ctrl+Z)는 일시 중지(fg로 재개)
- **kill() 시스템 콜**: 프로세스에 시그널을 보내는 시스템 콜. 이름과 달리 종료뿐 아니라 다양한 시그널 전송 가능
- **signal() 시스템 콜**: 특정 시그널을 catch해서 커스텀 처리를 등록하는 함수
- **사용자(User) vs 슈퍼유저(root)**: 일반 사용자는 자기 프로세스만 제어 가능. 슈퍼유저(root)는 모든 사용자의 프로세스를 제어 가능
- **waitpid()**: wait()의 더 완전한 버전. 특정 자식의 PID를 지정해서 기다릴 수 있음
- **exec() 6가지 변형**: execl, execlp, execle, execv, execvp, execvpe. l=list, v=vector, p=PATH검색, e=환경변수
- **Lampson's Law**: "Get it right" — 추상화나 단순함이 올바름을 대체할 수 없다. fork()+exec() 조합이 올바른 설계임을 강조하는 맥락에서 인용
- **pipe() 시스템 콜**: 커널 내 큐(파이프)를 만들어 한 프로세스의 출력을 다른 프로세스의 입력에 연결. fork()+exec() 사이의 틈에서 설정
- **PID (Process Identifier)**: 프로세스 식별자. UNIX에서 프로세스를 이름 짓고 제어하는 데 사용
- **유용한 도구**: ps(프로세스 목록), top(실시간 모니터링), kill/killall(시그널 전송), man pages(문서 확인, RTFM!)
